# إدارة العمولات (Provisionsmanagement) — دليل المشغّل

كل ما يخص العمولات صار في مكان واحد داخل عالم المستشار:
**القائمة الجانبية ← Provisionsmanagement**.

> ⚠️ هذه المنطقة **داخلية وسرّية**. لا يراها الزبون في البوابة، ولا يراها
> موظف بدون صلاحية العمولات — حتى لو فتح الرابط يدويًا.

## 1. الصفحات

| الصفحة | ماذا تُظهر |
|---|---|
| Dashboard | عمولة الشهر/السنة، عدد العقود المدفوعة وغير المدفوعة، المشاكل |
| Importe | كل عمليات الرفع (حتى المُلغاة) — سجل كامل |
| Abrechnungen | ملفات التسوية المؤكَّدة مع مجاميعها |
| Provisionsbuchungen | كل حركة عمولة على حدة |
| Verträge | العقد + تاريخ العمولة المتوقّعة + الحالة |
| Fehlende Provisionen | العقود التي لم تصل عمولتها + متابعة الحالة |
| Unklare Zuordnungen | ما لم يُربط تلقائيًا (لم يتم التخمين عمدًا) |
| Auswertungen | تحليل حسب المزوّد/المنتج/النوع/الشهر/الزبون + تصدير CSV |
| Einstellungen | المزوّدون (Pools) ومُهَلهم |

## 2. استيراد تسوية جديدة (خمس خطوات)

1. **Provisionsmanagement ← Importe ← „Neue Abrechnung importieren“**
2. اختر **المصدر (Pool)** — منه تُحسب المهل. إن تركته فارغًا يقترحه النظام
   من شكل الملف.
3. ارفع الملف (CSV / XLS / XLSX). النوع يُعرف من **محتوى** الملف لا من
   امتداده.
4. **المعاينة**: كم سطرًا سيُربط، كم عقدًا/زبونًا جديدًا، كم يحتاج مراجعة.
   حتى هذه اللحظة **لم يُكتب أي شيء**.
5. **Bestätigen** — عندها فقط تُسجَّل العمولات.

نفس الملف مرتين ⇒ **لا تكرار**. السطر غير المرتبط **لا يضيع**: يُحفَظ بلا عقد
ويظهر في „Unklare Zuordnungen“.

## 3. المهل (الأهم)

لكل مزوّد رقمان في **Einstellungen**:

* **Erwartet nach (Monate)** — متى يُفترض أن تصل العمولة.
* **Prüffrist (Monate)** — بعدها يُعتبر العقد **بلا عمولة** ويدخل قائمة
  المتابعة.

مثال CHECK24: متوقّعة بعد 3 أشهر، مهلة الفحص 5 أشهر. عقد مضى عليه 6 أشهر
بلا عمولة ⇒ الحالة تصبح **«Provision fehlt»** تلقائيًا كل ليلة.

تغيير المهلة يسري **فورًا**: يعيد النظام حساب عقود ذلك المزوّد عند الحفظ.

## 4. عمولة ناقصة — ماذا أفعل؟

**Fehlende Provisionen ← bearbeiten** ثم سجّل الحالة:

`Offen` ← `Pool kontaktiert` ← `In Klärung` ← `Geklärt`

مع تاريخ التواصل واسم المسؤول وجواب المزوّد. اختيار **Geklärt** يُخرج العقد
من قائمة المتابعة نهائيًا؛ وإذا وصلت العمولة لاحقًا يعود النظام ويحدّث
الحالة إلى **«Provision erhalten»** من تلقاء نفسه.

## 5. CHECK24: الرقم المرجعي ورقم المزوّد

عند الإبرام لدينا **Referenz-Nr.**، ولاحقًا يعطينا CHECK24 رقمًا خاصًا به
(**Id**). أول ملف يحمل الرقمين معًا يُثبّت الرابط بينهما إلى الأبد — بعدها
يكفي رقم CHECK24 وحده لإيجاد العقد والزبون.

إذا ظهر رقمان مرجعيان مختلفان لنفس الـ Id ⇒ **لا يربط النظام شيئًا** ويضع
الحالة في قائمة المراجعة. هذا مقصود: ربط خاطئ يعني عمولة على عقد زبون آخر.

## 6. الإلغاء (Storno) والتصحيح

الحركتان تبقيان **جنبًا إلى جنب**، ولا يُمحى شيء:

```
AP        +3,07 €
APStorno  -3,66 €
------------------
Netto     -0,59 €
```

## 7. قواعد ثابتة

* لا يُخمّن النظام أبدًا: تطابق مزدوج أو تناقض ⇒ «مراجعة يدوية».
* لا يُعدّل الاستيراد بيانات العقد — الاستثناء الوحيد: **إضافة** رقم ناقص.
* لا يوجد زر حذف للبيانات المستوردة؛ الخطأ يُصحَّح بحركة مضادة، والسجل
  (Protokoll) يحفظ من غيّر وماذا ومتى.

## 8. على الخادم

```
php artisan provisionen:status-aktualisieren
```

يعيد حساب حالات العمولة يدويًا (يعمل تلقائيًا كل يوم 04:10).
